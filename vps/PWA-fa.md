# پیگیر وب ۴.۱۰.۰ - نصب روی آیفون و مرورگر

نسخهٔ وب در مسیر `/app/` همان VPS اجرا می‌شود. حساب‌ها، شرکت‌ها، جلسات و مصوبات با اندروید مشترک هستند؛ ورود تازه یا انتقال داده لازم نیست. پنل ساخت شرکت‌ها همچنان در `/admin/` است. برای استفاده از قابلیت‌های رزرو جلسه و درخواست تمدید در گوشی اندروید، نسخهٔ ۴.۱۰.۰ اپ را هم نصب کنید؛ کلاینت‌های قدیمی همچنان به سرور متصل می‌شوند.

در تنظیمات، یادآوری درصدی از مهلت و یادآوری‌های دستی قابل روشن/خاموش‌کردن هستند؛ درصد بین ۱ تا ۹۹ قابل ذخیره است. برای دریافت پوستهٔ جدید، از بخش «به‌روزرسانی برنامه» بررسی و اعمال نسخه را بزنید. [راهنمای به‌روزرسانی](UPDATES-fa.md).

## ارتقای نصب موجود با Nginx

بستهٔ `Peygir-4.10.0-nginx-vps.zip` را روی **همان پوشهٔ سورس نصب قبلی** باز کنید. پیش از جایگزینی کد، طبق راهنمای Nginx از داده‌ها پشتیبان بگیرید. پوشهٔ `.device-private`، تنظیمات Firebase، نام پروژهٔ Compose و volume داده را حفظ کنید. `init` را دوباره اجرا نکنید و از `down -v` استفاده نکنید.

از ریشهٔ سورس نصب قبلی:

```bash
sudo bash vps/scripts/peygir-nginx.sh up -d --build api
sudo bash vps/scripts/peygir-nginx.sh ps
curl --fail http://127.0.0.1:18300/health
curl --fail https://peygir.hydrocode.ir/app/manifest.webmanifest
```

نسخهٔ سلامت باید `4.10.0` باشد. Nginx فعلی کل مسیرها را به API هدایت می‌کند؛ پورت ۱۸۳۰۰، گواهی و تنظیمات Nginx تغییر نمی‌کنند. بستهٔ جدید، وب را هم داخل همان image قرار می‌دهد. دادهٔ آزمایشی به نصب شما وارد نمی‌شود. در نخستین اجرای نسخهٔ جدید، جدول‌های افزایشی وب ساخته می‌شوند.

این نسخه در محیط توسعه پیاده‌سازی و آزموده شده است؛ برای فعال‌شدن روی دامنهٔ واقعی، ارتقای بالا باید روی VPS انجام شود. ساخت Docker در محیط فعلی به علت اجرا نبودن Docker daemon آزموده نشده است.

## نصب و ورود کاربر

نشانی پس از ارتقای VPS:

**https://peygir.hydrocode.ir/app/**

۱. در آیفون، نشانی را با Safari باز کنید.
۲. از اشتراک‌گذاری، «Add to Home Screen / افزودن به صفحهٔ اصلی» را انتخاب کنید.
۳. پیگیر را از آیکون صفحهٔ اصلی باز کنید و کد شرکت، نام کاربری و رمز همان حساب را وارد کنید.
۴. از تنظیمات برنامه، «فعال کردن اعلان روی این گوشی» را بزنید و مجوز اعلان را تأیید کنید.

اعلان وبِ نصب‌شده روی صفحهٔ اصلی به iOS/iPadOS 16.4 یا جدیدتر نیاز دارد. اجازهٔ اعلان باید با اقدام مستقیم کاربر درخواست شود. نیازی به حساب پولی توسعه‌دهندهٔ اپل برای این روش نیست. [توضیح رسمی WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

در Chrome اندروید یا رایانه، از منوی مرورگر یا گزینهٔ «نصب پیگیر» در تنظیمات استفاده کنید. به‌روزرسانی وب با بستن همهٔ پنجره‌های پیگیر و بازکردن دوباره فعال می‌شود؛ برنامه وسط فرم شما خودکار بارگذاری مجدد نمی‌شود.

## امکانات این نسخه

- رابط فارسی، راست‌به‌چپ، فونت وزیرمتن و رنگ روشن/تیره/همراه گوشی.
- جلسات روزانه و هفتگی ساعتی و ماهانهٔ شمسی؛ شروع از ساعت فعلی، جابه‌جایی لمسی و ثبت از فضای خالی تقویم.
- ثبت کوتاه جلسه با عنوان، زمان و افراد؛ جزئیات اختیاری، تکرار محدود، هشدار تداخل افراد و کپی جلسه.
- ثبت و واگذاری مصوبه، پیشنهاد مسئول و مخاطب، اولویت، سررسید شمسی و پیگیری پیش‌فرض یک روز قبل.
- فهرست تدریجی، جست‌وجوی جلسه/افراد و مصوبه/مسئول، فیلترهای جمع‌وجور و نشان تعداد.
- ارسال برای تأیید مدیر، تأیید نهایی، ثبت نتیجهٔ یک‌خطی، تمدید/تعویق با گزارش و اشتراک خلاصه.
- مدیریت کاربران با همان نقش‌ها و قواعد سرور؛ کاربر عادی فقط مصوبات خود و جلسات دعوت‌شده را می‌بیند.
- چند حساب شرکت روی **همین نشانی سرور**؛ لمس نام شرکت، انتخاب حساب را باز می‌کند. اعلان، ابتدا حساب خودش را انتخاب می‌کند. برای شرکتی روی VPS دیگر، نشانی وب همان VPS را جداگانه باز یا نصب کنید.
- نگهداری دادهٔ دریافت‌شده و تغییرات ثبت‌شده در IndexedDB، با صف ارسال مستقل هر حساب. تعارض واقعی پیش از بازنویسی به کاربر نشان داده می‌شود.

موتور صوت آفلاین Vosk، فایل صوتی، OCR، ویجت اندروید و تنظیمات ویژهٔ اندروید به وب منتقل نشده‌اند. این نسخه یک کلاینت وب مستقل برای کارهای اصلی است. نصب PWA به معنی نصب APK روی آیفون نیست.

## همگام‌سازی و حالت آفلاین

هنگام باز بودن برنامه، تازه‌سازی دوره‌ای حدود هر ۳۰ ثانیه، با بازگشت به صفحه و با اتصال دوباره انجام می‌شود؛ دکمهٔ بالای صفحه هم تازه‌سازی دستی دارد. پس از خطا، فاصلهٔ تلاش‌های بعدی ۱۰، ۳۰، ۶۰، ۱۲۰ و حداکثر ۳۰۰ ثانیه است. ارسال تغییرات پس از ثبت آغاز می‌شود و شناسهٔ عملیات در تلاش مجدد ثابت می‌ماند.

پس از ورود و بارگذاری اولیه می‌توانید دادهٔ دریافت‌شده را بدون اتصال ببینید و تغییرات را روی همان دستگاه ثبت کنید. داده‌ها پس از اتصال و بازبودن برنامه ارسال می‌شوند. ارسال در حالت بسته، Background Sync یا اجرای دائمی در پس‌زمینه وعده داده نمی‌شود. پاک‌کردن داده‌های مرورگر، استفاده از حالت خصوصی یا حذف ذخیره‌سازی توسط سیستم می‌تواند دادهٔ محلی، از جمله تغییرات ارسال‌نشده را پاک کند. برای خروج امن از حساب، اتصال لازم است؛ خروج دادهٔ محلی همان حساب را پاک می‌کند.

اولین دریافت اطلاعات حجیم مرحله‌ای است؛ پس از دریافت نخستین صفحه، داده‌ها نمایش داده می‌شوند. فهرست‌های معمول از ۵۰ مورد شروع می‌شوند و با اسکرول ادامه می‌یابند. سقف فعلی موجودی همگام‌سازی ۱۰هزار رکورد در هر حساب است.

## اعلان‌های وب از VPS

اعلان وب از Web Push و کلیدهای VAPID استفاده می‌کند و به تنظیمات Firebase اندروید وابسته نیست. کلیدها در اولین اجرای وب، در `registry.sqlite` ساخته و نگهداری می‌شوند؛ با هر restart عوض نمی‌شوند و با پشتیبان کامل VPS حفظ می‌شوند. فایل کلید تازه‌ای برای کاربر یا مدیر شرکت لازم نیست. [کتابخانهٔ Web Push](https://github.com/web-push-libs/web-push)

- دعوت تازه، واگذاری مصوبه و تغییرات مرتبط از صف تراکنشی ارسال می‌شوند؛ تغییرات اندروید نیز اعلان وب تولید می‌کنند.
- VPS هر دقیقه یادآوری‌های مصوبات، مرور روزانه و یادآوری اختیاری جلسه را بررسی می‌کند. ساعت‌های این نسخه **به وقت تهران** هستند؛ مرور صبح پیش‌فرض ۰۸:۰۰ است. یادآوری قبل جلسه پیش‌فرض خاموش است.
- با فعال‌بودن مجوز، اعلان در حالت باز یا بستهٔ برنامه قابل دریافت است؛ لمس اعلان شرکت و مورد درست را باز می‌کند. رسیدن Web Push به اینترنت، سیستم‌عامل، وضعیت مجوز و سرویس تحویل مرورگر وابسته است و تضمین ثانیه‌ای ندارد.
- فقط عنوان عمومی رویداد، نام شرکت و شناسه‌ها ارسال می‌شوند؛ عنوان یا شرح خصوصی جلسه و مصوبه در متن Push ارسال نمی‌شود.
- تنظیمات اعلان هر حساب مستقل است. پیش‌فرض اعلان دستیار خاموش است؛ در تنظیمات همان حساب می‌توان روشن کرد. مرور روزانه و یادآوری‌ها فقط برای مرورگری ارسال می‌شوند که مشترک اعلان شده باشد.
- دسترسی در لحظهٔ ارسال دوباره بررسی می‌شود. حساب حذف‌شده یا غیرفعال و نشست لغوشده اعلان دریافت نمی‌کند؛ اشتراک منقضی از صف ارسال حذف می‌شود.

VPS باید اتصال خروجی HTTPS به سرویس‌های Web Push مرورگرها، از جمله Apple و Google، داشته باشد. اطلاعات اصلی شرکت‌ها همچنان روی VPS شما هستند. وضعیت Firebase اندروید تأییدی برای اشتراک اعلان مرورگر نیست؛ آن را در نسخهٔ وب جداگانه فعال کنید.

## امنیت و پشتیبان

نشست وب در کوکی `HttpOnly`، `Secure` و `SameSite=Strict` نگهداری می‌شود؛ توکن بومی در JavaScript، IndexedDB یا Local Storage ذخیره نمی‌شود. عملیات تغییردهنده علاوه بر نشست به Origin دقیق و CSRF معتبر نیاز دارند. کد شرکت از مسیر پروفایلِ تأییدشدهٔ سرور استخراج می‌شود. Service Worker فقط فایل‌های عمومی برنامه را کش می‌کند و پاسخ API، حساب‌ها و جلسات را وارد Cache API نمی‌کند.

داده‌های کاری در IndexedDB مرورگر همان دستگاه نگهداری می‌شوند؛ دستگاه مشترک را قفل کنید و پس از استفاده از حساب خارج شوید. پشتیبان استاندارد VPS شامل داده‌های شرکت‌ها و کلیدهای VAPID است. بازیابی، نشست‌های وب و گوشی و صف‌های ارسال قبلی را لغو می‌کند؛ کاربران باید دوباره وارد و اعلان مرورگر را فعال کنند.

## توسعه و آزمون

Node.js 24.21 تا قبل از 25 لازم است. برنامهٔ وب نیاز به مرحلهٔ build یا CDN ندارد. Docker وابستگی‌های زمان اجرا را با lockfile نصب می‌کند.

```bash
npm ci --prefix vps
npm test --prefix vps
cd vps
npx playwright install chromium webkit
npx playwright test
```

محیط تست، دو شرکت ساختگی با ۵۰ کاربر، ۲۰۰ جلسه و ۵۰۰ مصوبه برای هر شرکت می‌سازد؛ به VPS واقعی وصل نمی‌شود. گزارش و محدودیت‌های آزمون در [گزارش PWA](../verification/PWA-fa.md) هستند. بستهٔ نصب شامل راهنمای حاضر است؛ گزارش‌های توسعه در مخزن سورس نگهداری می‌شوند.
