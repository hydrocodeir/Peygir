# اصلاح خطای دسترسی فایل‌های خصوصی هنگام نصب

اسکریپت init با umask برابر ۰۷۷، mode درخواستی ۰۶۴۴ را به ۰۶۰۰ تبدیل می‌کرد. در نصب root روی لینوکس، کاربر غیرریشهٔ API نمی‌توانست `/run/secrets/admin_bootstrap` را بخواند. تست‌های قبلی مبتنی بر mount فایل ویندوز این مجوز POSIX را پوشش نداده بودند. مشکل با initializer قبلی روی لینوکس بازتولید شد.

اصلاح: فایل ابتدا با ۰۶۰۰ و flag اختصاصی wx ساخته می‌شود و فقط سه JSON mountشده پس از نوشتن chmod صریح ۰۶۴۴ می‌شوند. پوشهٔ خصوصی ۰۷۰۰ و تنظیمات/اطلاعات ورود ۰۶۰۰ هستند. اجرای دوباره، محتوای موجود را بازنویسی نمی‌کند. برای نصب فعلی، دستور chmod روی همان سه فایل و recreate API کافی است؛ رمز/داده تغییر نمی‌کند. راهنماهای اصلی و Nginx دستور رفع خطا دارند.

۲۷ تست init/API/push در Docker لینوکس با ساخت فایل تحت root، بررسی mode واقعی و خواندن همان inode با uid=1000 موفق شدند؛ صفر شکست/skip. دو تست initializer روی ویندوز نیز موفق‌اند؛ ادعای mode واقعی فقط مربوط به لینوکس است. [گزارش](secret-permissions-checks.json). APK و منطق API تغییر نکرده‌اند؛ Android و تست‌های Nginx/TLS پیشین در این نوبت دوباره اجرا نشده‌اند. رفع خطا روی VPS عمومی باید با فرمان‌های راهنما توسط کاربر انجام شود.

بستهٔ اصلاح‌شده `Peygir-4.2.0-nginx-vps-fix1.zip` و checksum جدا آماده‌اند؛ فایل ZIP تحویل قبلی بازنویسی نشده است.

# بررسی حالت استقرار با Nginx موجود

بستهٔ مستقل `Peygir-4.2.0-nginx-vps.zip` برای `peygir.hydrocode.ir`، بدون تغییر APK یا منطق API، آماده شد. Compose مخصوص فقط سرویس api را از پیکربندی اصلی به ارث می‌برد و روی `127.0.0.1:18300:3000` منتشر می‌کند. wrapper تمام فرمان‌های نگهداری را به همین فایل هدایت می‌کند؛ Caddy در این حالت وجود ندارد. فایل HTTP اولیه، ACME را پاسخ می‌دهد و API را روی HTTP ارائه نمی‌کند؛ فایل نهایی، HTTPS با گواهی دامنه، مسیر تمدید، هدایت HTTP و بازنویسی IP پراکسی دارد. hook تمدید فقط برای گواهی همین دامنه، پس از صحت تنظیم، Nginx را reload می‌کند.

پیکربندی Compose با Docker Compose واقعی، هر دو فایل Nginx با `nginx -t` و اسکریپت‌ها از نظر syntax بررسی شدند. یک Nginx واقعی ۱٫۳۰٫۶ و API ۴.۲ در Docker با حساب‌ها و CA ساختگی اجرا شدند: TLS با تأیید گواهی محلی، HSTS، هدایت HTTP، مسیر چالش، دارایی‌های پنل، ورود امن مالک، ساخت شرکت، عبور هدر شرکت و Authorization در ورود/همگام‌سازی، رد Origin بیگانه و رد دورزدن محدودیت ورود با X-Forwarded-For جعلی همگی موفق بودند. [گزارش](nginx-checks.json).

برای آزمون فایل Nginx بدون تغییر، API آزمایشی در فضای شبکهٔ مشترک روی loopback:18300 گوش می‌داد؛ در استقرار واقعی، Nginx میزبان از نگاشت Compose از ۱۸۳۰۰ به ۳۰۰۰ استفاده می‌کند که جداگانه اعتبارسنجی شد. گواهی واقعی Let’s Encrypt صادر نشده و تنظیمات روی VPS کاربر اعمال نشده‌اند. آزمون‌های نسخهٔ ۴.۲ در گزارش بعدی مربوط به انتشار برنامه‌اند و برای این تغییر تنظیمات دوباره اجرا نشده‌اند. image رسمی Nginx فقط برای آزمون محلی با اعتبارسنجی hash لایه‌ها دریافت شد؛ تنظیم پراکسی یا سرویس‌های کاربر تغییر نکردند.

راهنمای [نصب و نگهداری Nginx](../vps/NGINX-fa.md) در بسته قرار دارد. بستهٔ قبلی ۴.۲ بازنویسی نشده است؛ checksum این توزیع جداست.

# سابقهٔ بررسی پیگیر ۴.۱.۰ — نقش افراد و مدیریت حساب‌ها

نسخهٔ ۴.۱.۰، کد ۲۹ روی برنچ `feature/vps-multitenant`. پایگاه گوشی ۶، پشتیبان گوشی ۴، پروتکل سازمانی ۲ و قالب پشتیبان سرور ۱ حفظ شده‌اند. APK و سرور VPS به‌صورت جفت ارتقا داده شوند.

- «کاربر جدید» نام و نام کاربری شخص را می‌گیرد و نقش مدیر، دستیار یا کاربر به او اختصاص می‌دهد. نقش بر اساس نام کاربری تعیین نمی‌شود. مدیر می‌تواند مدیر/دستیار/کاربر ایجاد و نقش افراد را تغییر دهد؛ دستیار فقط کاربران عادی را مدیریت می‌کند.

- تصمیم مجوز و بررسی آخرین مدیر داخل تراکنش با ثبت تصمیم در سابقهٔ حساب انجام می‌شوند. CAS حساب جلوی بازنویسی تغییر هم‌زمان را می‌گیرد. حذف خود، حذف/تنزل آخرین مدیر فعال و تلاش دستیار برای دادن نقش بالاتر رد می‌شوند. بازیابی مدیر از پنل سامانه پس از حذف/تنزل مدیر اولیه، یک مدیر فعال دیگر را انتخاب می‌کند.

# گزارش تاریخی پیگیر ۴.۰.۰ — VPS شخصی و شرکت‌های مستقل

برنچ `feature/vps-multitenant`، نسخهٔ اندروید ۴.۰.۰ و کد ۲۸. پایگاه گوشی ۶، پشتیبان گوشی ۴ و بدنهٔ پروتکل سازمانی ۲ حفظ شدند. استقرار عمومی و انتقال شرکت واقعی به زمان آماده‌شدن VPS موکول است.

## نتیجهٔ پیاده‌سازی

- سرویس Node 24.21 با SQLite بومی و بدون وابستگی npm زمان اجرا، با همان منطق دسترسی سازمانی. هر شرکت فایل پایگاه جدا دارد؛ رجیستری، حساب مالک و نشست پنل در پایگاه مرکزی جدا هستند. درخواست بدون کد معتبر شرکت، توکن شرکت دیگر، واگذاری به کاربر شرکت دیگر و تلاش معاون برای تأیید نهایی رد می‌شوند.
- پنل فارسی با منابع/فونت محلی برای ساخت شرکت و رئیس اولیه، تعلیق/فعال‌سازی و بازیابی رمز رئیس. نام کاربری در شرکت‌های مختلف مستقل است. نشست مالک، کوکی امن HttpOnly/SameSite، کنترل Origin و CSRF دارد؛ پنل، محتوای جلسات و مصوبات شرکت‌ها را عرضه نمی‌کند. ثبت‌نام آزاد وجود ندارد.

APK و APK آزمون دستگاهی ساخته شدند. گزارش‌ها: [خلاصهٔ اپ](check-summary.json)، [آزمون‌های سرور](cloudflare-organization-tests.xml)، [آزمون آنلاین](cloudflare-organization-smoke.json)، [اعتبارسنجی FCM](firebase-check.json).

- اندروید: مهاجرت واقعی پایگاه نسخهٔ ۵ به ۶، حفظ رکورد و حذف ارسال‌نشدهٔ دارای payload قدیمی، تقویم و تکرار شمسی با ماه کوتاه و بدون جابه‌جایی تدریجی روز، حساب مسئول و تأیید در SQLite/فرم/پشتیبان، پاک‌شدن دادهٔ سازمان هنگام خروج و جست‌وجوی نام با ی/ک عربی بررسی شدند.
- رابط: انتخاب حساب مسئول شناسهٔ درست را ذخیره می‌کند؛ معاون فرم ویرایش عنوان/موعد ندارد، گزارش می‌نویسد و برای بررسی می‌فرستد. جست‌وجوی شرکت‌کننده جلسهٔ ماه قبل را می‌یابد و سه حالت تقویم کار می‌کنند. آزمون‌های قبلی صوت، پیش‌نویس، مصوبات، حذف جلسه، تعارض فرم، اعلان، ویجت و پشتیبان برقرارند.
- FCM: همان پیاده‌سازی JWT با Web Crypto، از Google توکن OAuth موفق گرفت و API پیام، توکن دستگاه ساختگی را طبق انتظار رد کرد؛ هیچ اعلان واقعی در این بررسی ارسال نشد. پیام حساب دیگر نادیده گرفته می‌شود و رویداد تکراری پس از حذف اعلان دوباره نمایش داده نمی‌شود. کلید سرویس فقط Worker Secret است.

## سرویس آنلاین

روی Worker و D1 مستقر، دو حساب واقعی وارد شدند؛ مصوبه با حساب مسئول ثبت و دریافت شد، گزارش انجام به REVIEW رفت، تأیید دستیار رد و تأیید رئیس ثبت شد و به دستیار برگشت. تکرار همان عملیات نسخهٔ تازه نساخت. پیکربندی اعلان از API معتبر دریافت شد. رکوردهای ساختگی در پایان tombstone و نشست‌های همین آزمایش باطل شدند. آزمون مجوز معاون‌ها در Workers runtime/D1 محلی اجرا شد؛ حساب معاون ساختگی در سرویس اصلی اضافه نشد.

## تغییرات بررسی‌شده

- چهار بخش با HorizontalPager و کشیدن افقی در RTL جابه‌جا می‌شوند؛ انتخاب نوار پایین هماهنگ است. نوار کوتاه بالای محتوا محل روشن تغییر بخش است؛ کشیدن فهرست مرور فقط روز را تغییر می‌دهد. تست حرکت بین همهٔ بخش‌ها و استقلال مرور موفق است.
- جست‌وجو و روز مرور پس از رفت‌وبرگشت بین بخش‌ها و تنظیمات حفظ می‌شوند؛ دکمهٔ پاک‌کردن جست‌وجو اضافه شده است.
- فلش ماه قبل در سمت راست رو به راست و ماه بعد در سمت چپ رو به چپ اصلاح شد. عبور اسفند/فروردین، حفظ انتخاب تا تأیید و غیرفعال‌شدن حرکت پیش از ۱۲۰۰ آزمون دارند. امروز حاشیه دارد و تأیید تاریخ برجسته است. شبکهٔ روزها فشرده‌تر و «امروز» در نوار ثابت پایین در دسترس است.
- مسئول و سررسید با متن خواناتر و برچسب امروز، وضعیت فعال با نشان رنگی، اولویت جدا از نام جلسه و تیک وضعیت فعلی در منو نمایش داده می‌شود.

- فرم مشترک ثبت با انتخاب «نوشتن/صدا/عکس»؛ صفحهٔ جداگانهٔ دستیار حذف شده است. روش‌های ورودی به همان عنوان، مسئول و سررسید قابل ویرایش منتهی می‌شوند.
- نمایش جمع‌وجور KPIها و ردیف‌های مصوبات؛ حذف کارت معرفی/گزارش بزرگ و دکمهٔ شناور روی محتوا. ثبت از بالای همهٔ صفحه‌ها در دسترس است. اولویت، وضعیت و توضیحات جمع‌شونده‌اند.
- تأیید قبل از ثبت، انصراف بدون ثبت، نگهداری پیش‌نویس و حرکت به پیشنهاد بعدی فقط پس از ذخیرهٔ صریح.
- مرور روزانه با کشیدن افقی، روز قبل/بعد، هفته، انتخاب‌گر شمسی، بازگشت به امروز و حفظ روز انتخاب‌شده بین صفحه‌ها. ثبت از مرور، سررسید را روی همان روز می‌گذارد.
- حالت سررسید/یادآوری، نگهداری مصوبات انجام‌شده در روز مربوط، نمایش جلسه و صوت همان روز و جلوگیری از تکرار مصوبهٔ دارای چند یادآوری. فهرست ۲۰۰۰ مصوبه در محاسبهٔ مرور محدود یا بریده نمی‌شود و نمایش صفحه با LazyColumn انجام می‌شود.
- لمس یادداشت صوتی در مرور، پخش و تبدیل اختیاری را داخل فرم مشترک نشان می‌دهد؛ تبدیل گفتار صرفاً با مرور فایل آغاز نمی‌شود. ضبط تازه پس از پایان، به‌صورت خودکار وارد مرحلهٔ تبدیل و پیشنهاد می‌شود.
- آیکون تطبیقی تازه با مفهوم «برگهٔ تصمیم، حلقهٔ پیگیری و تیک»، لایهٔ تک‌رنگ مستقل و خروجی ۵۱۲ پیکسل. پیش‌نمایش اندازه‌های ۱۶۰، ۹۶، ۶۴، ۴۰ و ۲۴ پیکسل و حالت تک‌رنگ رندر و مشاهده شد.

## محیط ساخت و محدودیت بررسی

محیط Windows، JDK 17، SDK 35 و Gradle 8.11.1 است. Proxifier محدودهٔ UDP موقت سیستم را پُر کرده بود و Gradle پیش از کامپایل با خطای bind مواجه شد. گزینهٔ اختیاری `build-local.ps1 -UseFixedUdp` فقط انتخاب پورت ارتباط قفل کش Gradle را در فرایند ساخت به یک پورت آزاد صریح تغییر داد؛ تنظیمات سیستم و Proxifier تغییر نکردند. منبع این عامل در `scripts/local-build` است و بررسی DEX تأیید کرد وارد APK نشده است. ساخت عادی Android Studio به این عامل وابسته نیست.

گوشی Samsung Galaxy A53 با اندروید ۱۶ / API 36 متصل و نسخهٔ ۱.۲.۰ روی ۱.۱.۰ نصب شد. حفظ تمام ردیف‌های قبلی، پنج سناریوی رابط/موتورهای بومی، ضبط و پخش واقعی با تأیید کاربر، و دو یادآوری واقعی در پس‌زمینه بررسی شدند. نتیجه و محدودیت‌های دقیق در [DEVICE-RESULTS.md](DEVICE-RESULTS.md) و [device-check-summary.json](device-check-summary.json) ثبت شده‌اند. این بررسی شامل دوربین، دست‌خط، Doze اجباری یا راه‌اندازی مجدد نبود. APK اصلی تغییر نکرد؛ وابستگی‌ها و منابع Instrumentation برای اجرای تست دستگاه به سورس اضافه شدند.
