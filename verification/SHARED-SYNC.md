# پیگیر ۲ — فضای مشترک

سرویس با Cloudflare Workers و D1 روی حساب کاربر مستقر شده است. نشانی عمومی API در `gradle.properties` و `verification/cloudflare-smoke.json` ثبت است؛ این نشانی کلید دسترسی نیست. اطلاعات دفتر فقط پس از ورود حساب معتبر خوانده یا نوشته می‌شوند.

## راه‌اندازی دو گوشی

۱. APK یکسان پیگیر ۲ را روی هر دو گوشی، روی نسخهٔ قبلی نصب کنید.
۲. در تنظیمات، «فضای مشترک با مدیر» و «ورود به فضای مشترک» را باز کنید. نشانی سرویس در APK آماده است.
۳. روی گوشی دستیار، حساب assistant و روی گوشی مدیر، حساب manager را انتخاب کنید. رمز متفاوت هر حساب در فایل خصوصی همان حساب، زیر `.device-private/cloudflare` است؛ این فایل‌ها وارد سورس/گزارش عمومی نمی‌شوند.
۴. اگر گوشی اطلاعات قبلی دارد، پیش از اولین اتصال تعداد جلسات و مصوبات و تأیید افزودن آن‌ها به دفتر مشترک نمایش داده می‌شود. بدون این تأیید، اطلاعات فعلی ارسال نمی‌شود. افزودن، جایگزین‌کردن اطلاعات گوشی دیگر نیست.
۵. برای کنترل اولیه، یک مصوبهٔ آزمایشی ثبت و روی گوشی دوم «همگام‌سازی اکنون» را بزنید؛ وضعیت را تغییر دهید و برگشت نتیجه را بررسی کنید.

هر دو حساب به همان دفتر دسترسی نوشتن دارند. نقش‌ها نام و پیش‌فرض اعلان را تعیین می‌کنند: مدیر فعال، دستیار غیرفعال؛ از «یادآوری در این گوشی» تغییر می‌کند. خاموش‌کردن یادآوری، حساب یا همگام‌سازی را قطع نمی‌کند. صوت خام، آرشیو صوتی، فایل ZIP پشتیبان، دادهٔ قدیمی مخزن و تنظیمات شخصی همگام نمی‌شوند.

## زمان دریافت و اعلان

با اپ باز، همگام‌سازی هنگام ورود/ثبت و حدود هر ۳۰ ثانیه بررسی می‌شود. با اپ بسته، JobScheduler کار دوره‌ای با اینترنت و فاصلهٔ درخواستی ۱۵ دقیقه دارد؛ اجرای واقعی تابع باتری، Doze و محدودیت‌های گوشی است. این نسخه اعلان پوش فوری برای «مصوبهٔ جدید» ندارد و FCM به آن متصل نشده است. مصوبهٔ تازه تا دریافت اطلاعات در گوشی مدیر قابل یادآوری نیست. پس از دریافت، یادآوری‌های همان گوشی با AlarmManager فعلی اجرا می‌شوند؛ اعلان‌های انجام/تعویق تغییر کرده یا حذف‌شده به‌روزرسانی می‌شوند.

پرچم «اعلان تحویل شد» بین گوشی‌ها منتقل نمی‌شود؛ دریافت یک گوشی، اعلان دیگری را از بین نمی‌برد. زمان تعویق یک‌ساعته به‌عنوان زمان پیگیری مشترک منتقل می‌شود. مرور روزانه و ساعت‌های آن تنظیم همان گوشی‌اند.

## داده، خطا و ویرایش هم‌زمان

- SQLite نسخهٔ ۵، جدول‌های شناسهٔ مشترک، تغییرات ارسال‌نشده و تعارض را اضافه می‌کند. چهار بخش اصلی رابط و شناسه/امضای نصب حفظ می‌شوند.
- هر رکورد شناسهٔ UUID مستقل از شمارهٔ محلی دارد. API برای هر عملیات یک رسید تکرارپذیر و برای هر نسخه شمارهٔ افزایشی دارد. قطع ارتباط پس از ثبت سرور، ثبت تکراری ایجاد نمی‌کند؛ صف پس از بسته‌شدن اپ باقی می‌ماند.
- تغییر فیلدهای متفاوت خودکار ادغام می‌شود؛ مجموعهٔ زمان‌های یادآوری نیز ادغام می‌شود. اختلاف روی همان فیلد، هر دو نسخه را برای انتخاب در تنظیمات نگه می‌دارد. تغییرات ذخیره‌نشدهٔ فرم باز نیز با نسخهٔ تازه مقایسه می‌شوند و اختلاف بدون انتخاب کاربر ذخیره نمی‌شود.
- حذف جلسه، ارتباط مصوبات را جدا می‌کند؛ حذف مصوبه، نتایج و تاریخچهٔ مرتبط را حذف می‌کند. یادداشت ارسال‌نشده هنگام حذف هم‌زمان مصوبه، قبل از انتخاب کاربر نگه داشته می‌شود. درخواست فرزند با والد حذف‌شده، سایر موارد صف را مسدود نمی‌کند.
- خروج از حساب، ارسال را متوقف و نشست همان دستگاه را باطل می‌کند؛ دادهٔ محلی باقی است. اتصال قبلی برای جلوگیری از ارسال تصادفی به دفتر دیگر نگه داشته می‌شود. «جدا کردن اتصال قبلی» آن را فقط از این گوشی جدا می‌کند و هیچ حذف ابری نمی‌فرستد.
- بازیابی ZIP هنگام اتصال دفتر مشترک مسدود است. برای بازیابی باید ابتدا خارج و اتصال را صریح جدا کنید؛ پس از بازیابی، افزودن دوباره به دفتر یک واردکردن تازه است و می‌تواند موارد تکراری بسازد. اطلاعات همگام‌سازی و ورود داخل ZIP نیستند.

## حساب و نگهداری

رمزهای اولیه تصادفی و دارای ۱۲۸ بیت آنتروپی‌اند؛ در D1 فقط PBKDF2-SHA256 با نمک مستقل و ۱۰۰۰۰۰ دور ذخیره می‌شود. نشست‌های تصادفی ۲۵۶ بیتی در سرور هش‌شده‌اند و ۹۰ روز اعتبار دارند. در اندروید، نشست با AES-GCM و کلید Android Keystore ذخیره می‌شود؛ رمز ورود ذخیره نمی‌شود. API فقط HTTPS دارد، تغییر مسیر را دنبال نمی‌کند، دسترسی دفتر را سمت سرور بررسی و تلاش‌های ورود را برای هر IP محدود می‌کند. ساخت حساب از API عمومی وجود ندارد؛ فقط راه‌انداز Cloudflare می‌تواند حساب بسازد/غیرفعال کند.

توسعه و آزمون سرویس:

```powershell
cd cloudflare
npm.cmd ci
npm.cmd test
npm.cmd run db:local
npm.cmd run dev
```

استقرار و تغییرهای سرور با حساب مالک Cloudflare انجام می‌شود. قبل از اجرای مهاجرت روی دادهٔ واقعی، از D1 پشتیبان بگیرید. `cloudflare/scripts/provision.mjs` برای راه‌اندازی اولیه است؛ اگر فایل خصوصی حساب‌ها موجود باشد، دوباره رمز/دفتر نمی‌سازد. نباید SQL راه‌اندازی اولیه را روی پایگاهِ آماده تکرار کرد.

پوشه‌های `node_modules`، `.wrangler`، `.device-private`، فایل‌های `.env` و `.dev.vars` و کلید امضا از سورس تحویلی خارج‌اند. برنامه نیاز به خرید دامنه یا ارتقای پولی Cloudflare برای این پیاده‌سازی ندارد؛ ظرفیت و شرایط پلن رایگان تابع Cloudflare است.
