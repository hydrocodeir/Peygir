# بررسی انتشار خودکار سرور — ۴.۱۱.۰

Workflow انتشار، تست و بسته‌بندی وب/API را اجرا می‌کند؛ پس از موفقیت ساخت اندروید، ارتقای سرور و سپس انتشار APK انجام می‌شود. اجرای دستی `deploy-server` از main، فقط سرور را منتشر می‌کند. [راهنمای اجرا](../vps/AUTOMATIC-SERVER-fa.md).

بررسی‌های محلی موفق:

- ۶۲ آزمون VPS؛ شامل مهاجرت آفلاین شرکت فعال و غیرفعال، حفظ رکورد و revision، اجرای تکراری و جلوگیری از مهاجرت هنگام اجرای API.
- ۱۰ آزمون Python برای ابزارهای انتشار، بسته‌بندی عمومی، هش فایل‌ها و جلوگیری از ورود تنظیمات خصوصی.
- آزمون SSH ساختگی برای حفظ host key، عدم انتشار در حالت check، انتقال خطا و حذف کلید موقت.
- ۹ سناریوی Docker ساختگی: بررسی اتصال، انتشار موفق، سورس یکسان، شکست ساخت، اختلاف volume، شکست backup، شکست مهاجرت، شکست شروع و شکست سلامت عمومی. ساخت پیش از توقف، حفظ تنظیمات و تلاش برای راه‌اندازی image قبلی همراه با کنترل سلامت بررسی شد.
- ساخت واقعی image از سورس و از آرشیو انتشار، اعتبارسنجی واقعی Compose با `!reset null`، اجرای کانتینر فقط‌خواندنی با کاربر node، پشتیبان آفلاین، مهاجرت، راه‌اندازی مجدد و حفظ فایل آزمایشی روی volumeهای موقت. نتیجه در [گزارش Docker](server-automation-docker.json).
- بررسی syntax فایل‌های Bash، actionlint و `git diff --check` موفق.

تست Docker واقعی در `scripts/ci/tests/server_docker_integration.py` نیز در Workflow و پیش از انتقال به VPS اجرا می‌شود. volumeهای تست نام تصادفی `peygir-smoke-*` دارند و پس از آزمون حذف می‌شوند؛ به volumeهای نصب اصلی دسترسی ندارند.

آزمون‌های بازگشت کامل انتشار با Docker ساختگی اجرا شده‌اند؛ آزمون واقعی Docker، پشتیبان‌گیری و مهاجرت و راه‌اندازی را با دادهٔ آزمایشی بررسی کرده است. SSH واقعی، Nginx دامنه و انتشار روی VPS در این نوبت اجرا نشده‌اند. بازگشت خودکار فقط image را برمی‌گرداند و دیتابیس را از پشتیبان بازیابی نمی‌کند.
