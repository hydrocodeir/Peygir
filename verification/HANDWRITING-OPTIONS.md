# بررسی خواندن آنلاین دست‌خط فارسی

> سابقهٔ تحقیق: ورودی عکس و OCR در نسخهٔ ۱.۵.۰ از رابط حذف شده‌اند.

تاریخ بررسی: ۲۳ اکتبر ۲۰۲۶.

به‌روزرسانی: اتصال اختیاری Mistral در نسخهٔ ۱.۴.۰ پیاده‌سازی شده است؛ [راهنمای راه‌اندازی](MISTRAL-SETUP.md). گزارش زیر تحقیق اولیهٔ نسخهٔ ۱.۳.۰ است. اتصال زنده و دقت دست‌خط هنوز با کلید واقعی آزموده نشده‌اند.
 بررسی مستندات عمومی؛ هیچ عکس، صوت یا دادهٔ خصوصی گوشی به سرویس‌ها ارسال نشده و هیچ API پولی فراخوانی نشده است. این سند طرح ارزیابی است، نه نتیجهٔ آزمون دقت.

## نتیجهٔ پیشنهادی

برای ارزیابی اولیه، **Mistral OCR 4.1** نامزد مناسبی است: فارسی در فهرست OCR آن آمده و API ورودی تصویر دارد. این شواهد دقت دست‌خط فارسی، نام مسئول یا تاریخ شمسی شما را اثبات نمی‌کنند. پیش از انتخاب نهایی باید با نمونه‌های غیرمحرمانهٔ واقعی سنجیده شود. [زبان‌های رسمی](https://docs.mistral.ai/resources/languages)، [پردازش تصویر و سند](https://docs.mistral.ai/studio/document-processing/basic_ocr).

تعرفهٔ مستقیم OCR 4.1 هنگام بررسی **۴ دلار به ازای ۱۰۰۰ صفحه** است؛ مثلاً ۱۰۰ عکس تک‌صفحه‌ای حدود ۰٫۴ دلار هزینهٔ پایه دارد. هزینهٔ واسط، سرور و تبدیل ارز جداست. [مدل و تعرفهٔ رسمی](https://docs.mistral.ai/models/ocr-4-1).

برای دسترسی از ایران، **AvalAI** یک نامزد واسط دارای endpoint مستند `POST /v1/ocr` است؛ در مستندات فعلی آن مدل 4.0 با هزینهٔ ۰٫۰۰۴ دلار/صفحه درج شده است. این، آزمایش عملی دسترسی، پرداخت یا کیفیت نیست. مستندات واسط هنوز 4.0 را نشان می‌دهند، درحالی‌که سازنده 4.0 را منسوخ و 4.1 را جایگزین معرفی می‌کند؛ بنابراین مدل واقعاً ارائه‌شده باید قبل از اتصال مشخص شود. [API و تعرفهٔ واسط](https://docs.avalai.org/fa/api-reference/ocr)، [وضعیت 4.0 نزد سازنده](https://docs.mistral.ai/models/ocr-4-0).

سیاست عمومی AvalAI دربارهٔ API، فایل‌ها و نگهداری اطلاعات توضیح دارد، اما تعهد دقیقِ نگهداری/حذف عکس OCR و مسیر پردازش برای کاربرد سازمانی از این صفحه روشن نیست؛ قبل از ارسال اسناد جلسه باید روشن شود. هیچ تضمین «عدم نگهداری» یا «پردازش فقط داخل ایران» از این تحقیق حاصل نشده است. [سیاست رسمی](https://avalai.ir/privacy-policy/).

## مقایسهٔ گزینه‌ها

| گزینه | شواهد رسمی | نتیجه برای پیگیر |
| --- | --- | --- |
| Tesseract فعلی | مناسب متن چاپی؛ دست‌خط مسئلهٔ جداگانه است | آفلاین باقی می‌ماند؛ دست‌خط قابل اتکا نیست. [FAQ](https://tesseract-ocr.github.io/tessdoc/FAQ.html) |
| Google Cloud Vision | فارسی در OCR هست، اما خط عربی/فارسی در فهرست handwriting scripts نیست | برای دست‌خط فارسی انتخاب تضمین‌شده‌ای نیست. [زبان‌ها و خطوط](https://docs.cloud.google.com/vision/docs/languages) |
| Azure Vision Read | جدول دست‌خط فقط ۹ زبان را دارد و فارسی در آن نیست | نامزد اصلی این نیاز نیست. [زبان‌های دست‌خط](https://learn.microsoft.com/en-us/azure/ai-services/computer-vision/language-support) |
| Mistral OCR | فارسی و ورودی تصویر پشتیبانی می‌شوند | نامزد آزمون، با سنجش جداگانهٔ دست‌خط و تاریخ. [زبان‌ها](https://docs.mistral.ai/resources/languages) |
| Gemini | ورودی تصویر و پردازش چندوجهی دارد | نامزد مقایسه؛ کیفیت دست‌خط فارسی آزمایش نشده است. ایران در فهرست مناطق مستقیم Gemini API نیست. [تصویر](https://ai.google.dev/gemini-api/docs/image-understanding)، [مناطق](https://ai.google.dev/gemini-api/docs/available-regions) |

Vision برای OCR معمولی ۱۰۰۰ واحد اول ماه رایگان و از واحد ۱۰۰۱ تا ۵ میلیون، ۱٫۵ دلار/۱۰۰۰ واحد است؛ این قیمت به معنی پشتیبانی دست‌خط فارسی نیست. [تعرفه](https://cloud.google.com/vision/pricing).

Gemini رایگان برای سندهای جلسه مناسب ارزیابی پیش‌فرض نیست: شرایط آن استفاده از ورودی/خروجی برای بهبود محصولات و احتمال بررسی انسانی را توضیح می‌دهد و ارسال اطلاعات محرمانه به سرویس رایگان را منع می‌کند. [شرایط رسمی](https://ai.google.dev/gemini-api/terms).

## روش ارزیابی و اتصال بعدی

۱. ۲۰ تا ۳۰ نمونهٔ غیرمحرمانه از دست‌خط‌های معمول جلسه، نام افراد و تاریخ‌های شمسی رقمی آماده شود؛ رونویسی درست هرکدام مرجع سنجش باشد.
۲. فقط عکس انتخاب‌شده ارسال شود. متن خام، عنوان پیشنهادی، مسئول و تاریخ جداگانه با مرجع مقایسه شوند؛ علاوه بر خطای متن، نام/تاریخ ساختگی و تعداد اصلاح‌های لازم ثبت شوند.
۳. زمان پاسخ، هزینهٔ هر عکس، شکست اینترنت و امکان حذف ورودی بررسی شوند. نام مدل نسخه‌دار و تاریخ آزمون در نتیجه بیایند؛ صرف ادعای فروشنده معیار پذیرش نباشد.
۴. اگر نتیجه قابل قبول شد، در همان بخش «عکس» گزینهٔ «خواندن آنلاین» اضافه شود. ذخیرهٔ مصوبه همچنان فقط بعد از اصلاح و تأیید کاربر باشد؛ مسیر آفلاین نیز در دسترس بماند.
۵. کلید سازمانی در APK قرار نگیرد؛ یک سرور واسط کوچک با محدودیت مصرف، زمان انتظار و پاسخ خطای روشن نیاز است. نگهداری اسناد در سرور پیش‌فرض نباشد. سرویس/اعتبار API و محل استقرار هنوز انتخاب نشده‌اند.

**در نسخهٔ ۱.۳.۰ اتصال آنلاین پیاده‌سازی نشده است.** مجوز INTERNET و کلید API اضافه نشده‌اند؛ تحقیق عمومی تکمیل شده، اما اجرای پایلوت به سرویس قابل دسترس، اعتبار و نمونه‌های مجاز نیاز دارد.
